# 12단계 탈환 작전실

기존 자료실 첫 화면에 읽기 전용 작전실을 추가했습니다. 기존 로그인, 데모 승인, 메모 CRUD, 판정기·탐지 규칙과 복구 권한은 유지합니다. 설정 단계는 12입니다.

## 사용 준비

1. Supabase SQL Editor에서 `docs/OPERATIONS_AUDIT.sql`을 한 번 실행합니다. 가린 메타데이터만 보관하는 별도 `operations_audit` 테이블과 인덱스를 만듭니다. 기존 메모와 데모 승인 테이블은 변경하지 않습니다. 브라우저 역할의 직접 읽기·쓰기는 차단합니다.
2. 기존 `SUPABASE_URL`, `SUPABASE_SECRET_KEY`, `DEMO_APPROVAL_ADMIN_IDS` 서버 설정을 그대로 사용합니다. 새로운 키를 브라우저나 코드에 넣지 않습니다.
3. 배포 후 기존 화면에 관리자 계정으로 로그인하고 데모 접속 승인을 확인합니다. **탈환 작전실 → 서버 요약 새로고침**을 누릅니다. 승인 방법은 [기존 안내](DEMO_APPROVAL.md)를 따릅니다. 관리자 화면은 별도 창의 `/demo-approval.html`입니다.

관리자가 아니거나 현재 페이지 승인을 확인하지 못하면 요약 API는 거부합니다. 로그아웃·승인 취소로 기존 화면이 잠기면 작전실의 수치와 기록도 지워집니다. 실패 후 이전 수치를 그대로 보여 주지 않습니다.

## 화면이 뜻하는 것

| 항목 | 확인 근거 | 연결되지 않았거나 기록이 없을 때 |
|---|---|---|
| 판정기 규칙 | 서버가 실제 `RULE_IDS` 구현 목록을 읽음 | 실제 판정 실행 횟수는 미연결. 구현 개수를 허용·차단 횟수로 표시하지 않음 |
| 탐지 사건 | 운영 사건 수집 API는 현재 없음 | 미실행, 건수 `null`. 가상 연습 사건·시험 건수를 운영 사건으로 더하지 않음 |
| 실제 기기 회수 | 운영 회수 집행 API는 현재 없음 | 미실행, 건수 `null`. 아래 데모 취소와 구분 |
| 데모 접속 취소 | 관리자 취소 API에서 상태 변경을 확인한 뒤 저장한 기록 | 저장소 조회 불가는 `null`. 연결된 기록이 없으면 최근 기록 0건 |
| 메모 복구 버전 | 기존 복구 API가 ID·소유자·내용 해시 대조를 모두 마친 사본의 해시 | 기록 없으면 미실행(확인 기록 없음), 기록 조회 실패면 확인 불가 |
| 정책 복구 버전 | 격리 시험 CLI 기록은 서버에 연결하지 않음 | 미실행, 버전 `null`. 메모 사본 해시를 정책 버전으로 쓰지 않음 |

메모 복구 사본의 해시는 화면·요약 API에서 `sha256:` 뒤 12자리로 가립니다. 메모 본문·제목·메모 ID·소유자·로그인 토큰·기기 핸들·개인키는 감사 테이블과 요약 응답에 넣지 않습니다.

`GET /api/operations-summary`는 같은 응답 안에 요약 수치, 조회 시각, 스냅샷 번호, **수치 대조용 가린 서버 기록**을 반환합니다. 수치는 최신 저장 기록 최대 100건만 대상으로 하며, 전체 기간 합계가 아닙니다. 화면은 서버 수치와 가린 기록의 건수·규칙 목록·마지막 복구 버전을 다시 대조하고 어긋나면 수치 표시를 중단합니다.

기록은 이 기능을 연결한 뒤 확인된 API 결과부터 쌓입니다. 이전 실행을 추측해 채우지 않습니다. 감사 저장 실패는 기존 복구·승인 취소 결과를 뒤집지 않고 해당 API 응답에 `X-Operations-Audit: unavailable`을 표시합니다. 기록되지 않은 실행은 이 요약에 포함되지 않으므로 이력을 완전한 전체 실행 통계로 해석하지 않습니다. 감사 저장소 자체를 조회할 수 없으면 0건으로 채우지 않습니다.

## 확인

- `node --test test/operations-summary.test.mjs test/note-restore.test.mjs`: 서버 요약과 가린 기록·화면 수치 대조, 권한 거부, 미실행/조회 실패, 본문 제외, 확인된 결과의 감사 기록을 모의 저장소로 검사합니다.
- 화면의 **수치 대조용 가린 서버 기록**을 펼쳐 규칙 수와 복구/데모 취소 기록 수를 비교합니다. 동일 스냅샷 범위의 값끼리 비교합니다.
- `npm run bundle`의 12단계 자기 점검에는 무로그인 요약 요청이 401로 거부되는지 실제 HTTP로 확인하는 항목이 있습니다. JSON 생성이나 로컬 모의 시험을 공식 심판 판정으로 쓰지 않습니다.

이번 구현에서는 실제 DB 테이블 생성·배포·로그인·운영 복구·운영 사건 수집·실제 기기 회수·공식 심판을 실행하지 않았습니다. 첫 배포 전에 위 SQL 설정이 필요하며, 연결 전에는 규칙 목록만 확인되고 감사 기록은 조회 불가로 표시될 수 있습니다.
